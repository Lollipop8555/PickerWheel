# Picker Wheel · 大转盘

一个简约、优雅的在线大转盘，纯静态页面，可作为 PWA 安装到桌面并完全离线运行，可直接部署到 GitHub Pages。

## 特点

- **极简界面**：屏幕中央只有转盘，下方只有一个「开始」按钮，右上角是设置入口。
- **侧栏生成转盘**：点击右上角按钮，展开悬浮侧栏，输入内容即可生成转盘。窄屏（≤ 620px）下侧栏自动变为底部抽屉。
- **一行一份**：每行内容自动切分为一个扇区，行数决定份数。
- **连续相同项合并（环形判定）**：连续相同的行合并为一份并累加权重，展示上只显示一份内容。因为转盘是圆形，首尾在 0° 处相接，所以判断「相邻」时必须把末尾和开头也视为邻居：
  - `A / A / B / C` → 3 份，A 占 50%
  - `A / B / C / A` → 3 份，A 占 50%（首尾相接）
  - `A / B / A / C` → 4 份，两个 A 各占 25%（隔着 B 和 C，不相邻）
  - `A / B / B / A` → 2 份，A、B 各占 50%
  - `A / B / A / B` → 4 份，环形上严格交替，没有任何相邻同项
- **缓动旋转**：起步加速、匀速、末段平滑减速，默认 5 秒，可在侧栏手动设置（范围 5 ~ 600 秒）。
- **柔和配色**：莫奈 / 马卡龙色系，每一份颜色互不相同，风格清新自然。
- **自适应尺寸**：转盘直径取屏幕短边，横屏、竖屏、窄屏均能完整展示。
- **快捷方案**：内置摇骰子（1~6）、四选一（A/B/C/D）、正反抉择、正反交替 12 选一等方案。
- **链接分享**：转盘内容会被编码进 URL 的 `w` 参数，把链接发给别人，对方打开看到的就是同一个转盘。
- **本地记忆**：最近一次确认生成的转盘会以「最近使用」卡片出现在快捷方案末尾（标题是使用时间，描述是首条内容 + 项数）；转动时长单独记住，不参与分享。
- **PWA 离线可用**：支持安装到桌面/主屏（含 maskable 图标、应用快捷方式），首次访问后所有资源进入缓存，断网或飞行模式下照常使用。

## 使用

直接双击 [`index.html`](index.html) 即可在浏览器中打开，无需构建、无需服务器。

> 注意：以 `file://` 方式打开时功能完整，但**无法启用 Service Worker**（浏览器安全限制），因此拿不到「可安装 / 完全离线」能力。需要完整体验请用下方任意一种方式通过 HTTP 访问。

在设置侧栏中：

1. 在文本框内逐行输入选项，右侧实时预览转盘。
2. 按需修改转动时间（单位：秒，最少 5 秒）。
3. 点击「生成转盘」关闭侧栏，然后点击底部「开始」。
4. 需要分享时，在侧栏底部「分享链接」一栏点「复制」，把链接发给对方即可。

按空格键也可以触发转动（焦点不在输入框内时）。

### 分享链接

链接形如 `https://<站点>/?w=1.<base64url>`，**只有一个参数**：

- `w`：转盘内容。按整行内容做 UTF-8 + Base64URL 编码，并带版本前缀（当前为 `1.`），比 `encodeURIComponent` 短得多——中文尤其明显。打开链接时先按行切分并过滤空行，因此空行、首尾空格不会污染链接。
- 转动时长不写入链接：它是设备偏好，与「这是哪个转盘」无关。
- 无关的查询参数原样保留，但 `action=spin` 会被剔除——否则对方打开链接会直接自动开转。
- 编码后超过 1800 字符时不再生成链接，避免被聊天工具或二维码截断；此时侧栏会提示「内容过长，无法生成分享链接」。
- 打开带 `w` 参数的链接时，**链接内容优先于本地记录**；不带 `w` 时始终回落到默认的骰子 1~6。
- 以 `file://` 直接打开页面时无法生成分享链接（没有可分享的地址），侧栏会给出提示。
- 面板里的链接会随输入实时更新；点击「生成转盘」或切换快捷方案时，当前转盘才会同步写回地址栏（`history.replaceState`，不产生历史记录），所以直接复制地址栏同样可靠。输入过程中的草稿不会污染 URL。

## 部署到 GitHub Pages

推送到 `main` 分支即自动部署，详见下方「持续集成」。首次部署前需要一次性启用：

进入 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**。

GitHub Pages 默认启用 HTTPS，Service Worker 可以直接工作。首次访问后地址栏会出现安装入口，装到桌面即可离线使用。

### 本地预览

Service Worker 要求 `http(s)` 且对 `localhost` 放行，任选一种方式起一个静态服务器：

```bash
python3 -m http.server 8080
# 或
npx serve .
```

然后访问 `http://localhost:8080`。首次加载后可在 DevTools → Application → Service Workers 中确认已激活，勾选 Offline 即可验证断网可用。

## 文件结构

- [`index.html`](index.html) — 页面结构（转盘舞台、设置侧栏、底部按钮）与 PWA 元信息
- [`styles.css`](styles.css) — 视觉样式、侧栏动效与响应式布局
- [`app.js`](app.js) — Canvas 绘制、扇区合并算法、缓动旋转、预设方案、分享链接编解码与 SW 注册
- [`sw.js`](sw.js) — Service Worker：应用外壳预缓存、导航网络优先、静态资源缓存优先
- [`manifest.webmanifest`](manifest.webmanifest) — PWA 清单（名称、图标、主题色、应用快捷方式）
- [`icons/`](icons) — 应用图标（192/512、maskable、Apple Touch）
- [`favicon.svg`](favicon.svg) / [`favicon.ico`](favicon.ico) / `favicon-16/32.png` — 站点图标
- [`tools/generate-icons.mjs`](tools/generate-icons.mjs) — 图标生成脚本（纯 Node，无第三方依赖）

## 实现要点

- 扇区采用 Canvas 2D 绘制，按 `devicePixelRatio` 缩放，保证高分屏清晰。
- 文字沿半径排布并自动缩放，过长时省略；左半侧扇区自动翻转，避免文字倒置。
- 缓动曲线通过速度表积分归一化得到，保证 `t = 0` 与 `t = 1` 时速度均为 0，起停不突兀。
- 转盘首尾在 0° 处相接，因此「连续相同」按环形判断，`A/B/C/A` 也能正确合并。
- 分享链接的 UTF-8 编解码是手写的（不依赖 `TextEncoder`），因此 `file://` 打开和 Node 测试环境都能跑；按码位遍历，emoji 等代理对字符不会被拆坏。
- 离线优先：Service Worker 预缓存全部外壳资源，导航请求失败时回落到缓存的 `index.html`。因为导航请求带查询串也能命中缓存外壳，带 `w` 参数的分享链接在离线状态下同样可用。

## 图标

图标由脚本生成，不依赖任何设计软件或第三方库：

```bash
node tools/generate-icons.mjs
```

脚本手写 PNG 编码（zlib + CRC32）、ICO 容器封装，并以 4×4 ~ 8×8 超采样做抗锯齿。几点值得注意的实现细节：

- 图标用的是**比界面更深一档的色板**。界面上的莫奈浅色相对浅色背景对比度仅 1.1:1 ~ 1.4:1，在 16px 的标签页图标上会整片糊掉；图标色板把明度压到 55%~64%，使每个扇区相对白色背景的对比度都 ≥ 3:1。
- 抗锯齿时颜色按 alpha 加权平均。若把透明样本的 `rgb(0,0,0)` 也一并平均，边缘会被拉暗，在浅色背景上呈现出一圈发灰的脏边。
- 图标不含指针。16px 下指针会被压成一个看不出形状的小三角，反而显脏。
- maskable 版本把内容缩进到 80% 安全区内，避免被系统裁成圆形或圆角矩形时切掉扇区。

## 开发与测试

无第三方依赖，只需 Node.js 18+：

```bash
node tools/verify.mjs        # 静态自检：语法、manifest、资源引用、SW 清单、图标
node tools/test-core.mjs     # 核心逻辑测试：环形合并、命中判定、缓动、时长钳制
node tools/generate-icons.mjs # 重新生成全部图标
```

`test-core.mjs` 用 Node 的 `vm` 模块配合最小 DOM 桩直接执行 [`app.js`](app.js)，因此不需要浏览器或 Puppeteer。

## 持续集成

[`ci.yml`](.github/workflows/ci.yml) 在每次 push 与 PR 时运行，包含两个 job：

**`verify`** — 校验与测试：

1. 静态自检 + 核心逻辑测试
2. 重新执行图标生成脚本，若产物与仓库不一致则报错。这道检查能防止有人手改 PNG 导致图标与生成器脱节——图标只能是脚本的输出。

**`deploy`** — 部署到 GitHub Pages，仅在 `main` 分支的 push 时触发，且必须在 `verify` 通过后才会执行。

部署时先把运行时文件拷进 `dist/` 再发布，因此 `tools/`、`.github/` 不会出现在站点上。

### 启用 Pages

仓库推送后，进入 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**（不是 `Deploy from a branch`）。之后 `main` 分支的每次推送都会自动构建并发布。
